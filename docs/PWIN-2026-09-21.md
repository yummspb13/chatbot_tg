# P(win | условия входа) — 21.09.2026

Запрос владельца: «строим P(win | условия) — давай». Идея: калиброванная
вероятность выигрыша наших же сигналов по записанным при входе условиям, чтобы
пропускать входы ниже безубыточного порога ячейки. Правила зафиксированы до
данных; скрипты — `src/backtest/pwin/`, выгрузка и выводы —
`data/pwin-2026-09-21/` (`npx tsx src/backtest/pwin/pwin-model.ts`,
`… pwin-vol.ts`).

## Данные и правила

- 843 закрытые виртуальные сделки 01.08→18.09 (43 ячейки; 105 — BF-догонки по
  свечам, помечены флагом). Цель: win = pnl > 0 (базовая частота 0.597).
- Фичи только известные при входе: сторона; час UTC (две гармоники sin/cos);
  день недели (one-hot, среда — база); ln(спред / медиана инструмента);
  ln(вола окна / медиана инструмента); BF-флаг; участник (one-hot).
  `newsDistMin` пуст у всех — не используется.
- Модель: логрег с L2 (та же, что у fair-модели Polymarket). Группы по
  инструменту с n ≥ 90: BTC (333), WTI (127), EUR (123), GBPJPY (95), РФ-пул
  (100: SIBN/AFKS/GAZP/TRNFP/ALRS/SVCB/MOEX) + общая модель на всех 843.
- Сплит 70/30 по времени внутри группы; медианы и стандартизация — по train;
  λ ∈ {1, 10, 100, 1000} выбирается внутренним временным сплитом train.
- Вердикт 1: OOS log-loss и AUC против базы «частота участника на train»
  (сглаженная) и против константы.
- Вердикт 2: экономический гейт «пропуск, если P̂ < BE_wr ячейки», где
  BE_wr = avgLoss/(avgWin+avgLoss) по train ячейки (или по tp/sl сделки);
  p-value — перестановка внутри ячеек (столько же случайных пропусков).
- Устойчивость: те же метрики при сплитах 60/40 и 80/20 (всё отчитано).

## Вердикт 1 — модель против базы участника (test, сплит 70/30)

| группа | test | log-loss const / участник / модель | AUC участник / модель |
|---|---|---|---|
| BTC | 100 | 0.655 / 0.637 / **0.660** | 0.60 / 0.53 |
| WTI | 39 | 0.661 / 0.662 / **0.666** | 0.49 / 0.55 |
| EUR | 37 | 0.716 / 0.723 / **0.753** | 0.38 / 0.34 |
| GBPJPY | 29 | 0.715 / 0.600 / **0.655** | 0.71 / 0.70 |
| РФ-пул | 30 | 0.756 / 0.749 / **0.768** | 0.50 / 0.67 |
| всё (843) | 253 | **0.676** / 0.726 / 0.683 | 0.52 / 0.52 |

Модель хуже базы участника в 5 группах из 5; общая модель «обгоняет»
участника только потому, что база участника на 43 мелких ячейках сама хуже
константы — константу модель не бьёт. Единственный проблеск — AUC 0.67 у
РФ-пула на 30 сделках (ошибка AUC при таком n ≈ 0.1; при сплите 80/20 — 0.57).
Калибровка терцилей P̂ у BTC/WTI/EUR/всё — плоская (низ 0.52→факт 0.60, верх
0.69→0.60): предсказания не разделяют исходы.

## Вердикт 2 — экономический гейт «P̂ < BE ячейки» (test, живые сделки без BF)

| группа | test сд / pnl | пропуск сд | pnl пропущенных | остаток | perm-p |
|---|---|---|---|---|---|
| BTC | 39 / +43.6$ | 25 | +21.6$ | +22.0$ | 0.40 |
| WTI | 27 / +89.6$ | 27 | +89.6$ | 0 | 1.00 |
| EUR | 24 / +2.2$ | 19 | +1.0$ | +1.2$ | 0.65 |
| GBPJPY | 24 / −16.7$ | 21 | −15.6$ | −1.1$ | 1.00 |
| РФ-пул | 30 / +16.3$ | 14 | −4.8$ | +21.1$ | 0.06 |
| всё | 148 / +191.5$ | 104 | +118.0$ | +73.4$ | 0.03* |

\* p здесь означает «случайные пропуски того же счёта дали бы больше в 97%
случаев» — гейт выбирает хуже случайного.

Гейт **вырожден**: он режет 60-100% входов, потому что ячейки по построению
живут при WR ≈ BE_wr (tp40/sl80 → BE 0.67 при WR ≈ 0.70; край — несколько
процентных пунктов над порогом). Такой гейт работает только при реальной
разделяющей силе P̂, а её нет (вердикт 1). Там, где он пропускает часть
ячейки, отбор не лучше случайного (РФ-пул 0.06 при 70/30 → 0.26 при 80/20).

Вторичный гейт «срез нижнего квинтиля P̂» (граница с train): BTC +4$ при
p=0.010 (70/30) и p=0.147 (60/40), общая модель −19..−72$. Из 36 тестов
(6 групп × 2 гейта × 3 сплита) три с p < 0.05 при ожидаемых ≈ 1.8 — шум.

## Пост-хок: «низкая вола на входе → пропуск»

Описательная таблица показала сильный in-sample эффект: WR по терцилям волы
WTI 0.40/0.82/0.56, GBPJPY 0.32/0.75/0.69, всё 0.53/0.66/0.60. Проверено
честно как ОДНО правило (граница — нижний терциль инструмента по train,
вердикт — на тех же 30 % test, 6 групп):

| группа | train WR low / rest | test low: n, WR, pnl | test rest: n, WR, pnl | perm-p |
|---|---|---|---|---|
| BTC | 0.61 / 0.62 | 13, 0.69, +8.8$ | 26, 0.73, +34.8$ | 0.10 |
| WTI | 0.28 / 0.73 | 13, 0.69, +31.3$ | 14, 0.71, +58.2$ | 0.43 |
| EUR | 0.54 / 0.62 | 10, 0.60, +0.8$ | 14, 0.64, +1.4$ | 0.78 |
| GBPJPY | 0.33 / 0.76 | 7, 0.14, −5.6$ | 17, 0.59, −11.1$ | 0.35 |
| РФ-пул | 0.68 / 0.67 | 14, 0.50, −1.0$ | 16, 0.50, +17.3$ | 0.64 |
| всё | 0.50 / 0.65 | 60, 0.62, +74.8$ | 88, 0.61, +116.6$ | 0.27 |

На test эффект исчезает у WTI (пропуск стоил бы +31$), BTC, EUR, пула:
in-sample «низкая вола = минус» было режимом августа, не структурой.
Держится только GBPJPY (0.14-0.19 vs 0.59 на всех трёх сплитах; механизм —
57 % low-vol сделок gj-meanrev умирают по TIME, не дотянув до TP), но семейство
в минусе целиком, экономия 5$ на 7 сделках, perm-p 0.35. Не внедряем; это
довод на уровне семейства (жив ли gj-meanrev), а не гейта.

## Итог

**P(win | условия) = P(win | ячейка).** Записанные условия входа (спред, вола
окна, час, день недели, сторона) не несут OOS-информации сверх собственной
частоты участника; лучший предиктор исхода — какая ячейка торгует (у GBPJPY
одно знание участника даёт AUC 0.71). Это подтверждает уровень, на котором
система и принимает решения: отбор и прополка ячеек, а не фильтр сделок.

Что могло бы изменить ответ — более сильные условия, которых мы не пишем:
доходность за последние 1-4 часа, положение в дневном диапазоне, отношение
короткой волы к дневной, новостной балл (ждёт OPENAI_API_KEY). Их запись —
дешёвая докрутка на будущее; вернёмся к P(win) через 2-3 месяца форварда с
такими полями, не раньше.

Леджер: 259 985 → **259 997** (+6 моделей, +6 пост-хок; stage1 = 1 (GBPJPY
low-vol по знаку), stage2 = 0).

## Внедрено (решение владельца 21.09): расширенный контекст входа

Новая jsonb-колонка `agent_Trade.entryCtx` (DDL накатана в fxagent до деплоя,
Prisma `entryCtx Json?`), модуль `src/agent/entryctx.ts`. Пишется во всех
точках открытия сделок: виртуальные ансамбли (EUR/BTC/мультирынок/MOEX),
живая крипто-нога, живая FX-нога. Только запись — на торговые решения не
влияет. Поля, всё в пипсах масштабированного пространства ноги (как
`spreadAtEntry`/`volAtEntry`):

| поле | смысл | null когда |
|---|---|---|
| ret60 / ret240 / ret1440 | ход цены за 1 / 4 / 24 часа | нет сэмпла у нужной точки (допуск 5/15/30 мин) |
| rng60 / rng1440 | размах max−min за 1 / 24 часа | история покрывает < 80 % окна |
| pos1440 | положение цены в суточном диапазоне, 0..1 | нет суточного окна |
| gapMin | минут от предыдущей котировки ноги | первая котировка после старта |
| news | балл новостного фона по активу: Σ dir·conf·(1 − возраст/горизонт) за 96ч | прогнозов нет (скоринг ждёт OPENAI_API_KEY) |
| oilShock | знак нефтяного шока −1/0/1 (MOEX-нога, мультирынок) | нога без трекера |

Кольцо цен: даунсемпл 30 с, глубина 25 ч; сидируется прогревом Dukascopy
(ансамбли EUR/BTC/мультирынок, крипто-нога), у MOEX и живой FX-ноги
накапливается с первой котировки (суточные поля появляются через сутки после
рестарта). Синтетический тест: линейный рост 1 п/мин даёт ret60=60,
ret240=240, ret1440=1440, pos1440=1; разрыв 45 мин → gapMin 45; холодный
старт → null; MOEX 07:05 после ночи → ret1440 есть, часовые поля null.

Возврат к P(win | условия) — не раньше 2-3 месяцев форварда с этими полями
(заполняемость проверять с 22.09 по MOEX-ячейкам, остальное — после MetaApi).
